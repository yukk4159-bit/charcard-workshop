# design-spec.md 编写指南

`design-spec.md` 是跨 skill 交接物：tavern-design 写入叙事设计段，tavern-ui 在 UI 开发阶段追加 UI 段，tavern-cards 消费它。

## 产出位置

询问用户项目名称后，直接创建：

```
cards/{Project}/design-spec.md
```

该文件从创建起就留在项目目录中。叙事材料转化时，`故事大纲.yaml` 也保存在同一项目目录（`cards/{Project}/故事大纲.yaml`），与 `design-spec.md` 配套。

## 讨论原则

本阶段只做大方向级别的讨论。

用户个人独特的想法和思路是内容独创性的保障。你的任务是忠实记录用户需求，任何不确定之处都必须询问用户确认；即使用户没有确定思路，也只能通过启发式提问引导，严禁猜测、推断用户想法。

SFW/NSFW 维度隐私度高，举例时正向、负向、中性均衡，避免偏向；硬性边界先于喜好确认。

## 七个讨论维度

以下各维度的枚举内容仅供参考，启发表达，最终以用户选择为准。

### 1. 项目定位

- 项目名称
- 形式：角色卡（世界书内嵌）还是独立世界书
- 主题：角色扮演 / 模拟经营 / 冒险 / 日常 / 同人改编等，这是一个什么主题的作品？
- 体验目标：情感陪伴 / 攻略养成 / 悬疑解谜 / 自由冒险等，希望玩家获得什么体验？
- 情感落点：治愈 / 刺激 / 沉浸 / 陪伴 / 紧张释放，玩家最终在情感上得到什么

> 形式为独立世界书时，先确认其用途（剧情舞台 / 规则集 / 词典 / 工具人设），再决定后续哪些维度适用；无剧情、无开场、无 `<user>` 角色定位的独立世界书，相应维度跳过。

### 2. 世界观构思

- 世界基调、核心规则、时代/舞台
- 现实性基线：真实架空 / 半架空 / 完全架空
- 世界整体氛围：稳定日常 / 暗流涌动 / 危机四伏，仅作启发，不限定分类
- 与主题匹配的世界观概念
- 已有明确设定时，记录用户提供的方向；没有时可提出 2-4 个方向供用户选择

### 3. 角色构思

- 核心角色：姓名、身份、性格方向、关系方向
- 角色弧光方向：成长 / 沉沦 / 守恒 / 反转
- 与 `<user>` 的初始关系：陌生 / 熟识 / 对立 / 暧昧
- 角色间的张力关系：盟友 / 竞争 / 阶层 / 隐秘羁绊
- `<user>` 的角色定位：希望玩家扮演什么身份？保留多少自定义空间？
- 重要 NPC / 配角的初步方向
- 只确定「往哪个方向塑造」

> 独立世界书可能只有工具性 NPC / 词条人物，无核心角色弧光，按实际用途记录即可。

### 4. 互动与动态需求

- 玩家与角色/世界的主要互动方式
- 玩家能动性范围：完全自由 / 半引导 / 强剧情驱动
- 需要追踪的动态概念：关系变化 / 剧情进度 / 场景状态 / 经营数值等，只描述要追踪什么、为什么追踪
- 反馈循环节奏：即时 / 短期累积 / 长期养成
- 角色对玩家行为的反应走向

### 5. 创作方向

- 叙事视角：第一人称 / 第三人称
- 语言风格：口语化 / 文学化，轻松 / 严肃
- 文学密度：口语轻量 / 适度修辞 / 文风厚重
- 描写侧重：心理 / 动作 / 对话 / 环境
- 节奏偏好：紧凑推进 / 散文铺陈 / 跳跃蒙太奇
- 情绪基调：温馨 / 暗黑 / 搞笑 / 紧张 / 浪漫
- 风格参考（可选）：是否有想参考的作家或作品

### 6. 开场构思

- 故事开始时的情境
- 玩家进入世界的第一印象
- 开场信息密度：高浓度抛设定 / 渐进揭示 / 留白悬念
- 玩家首步引导方式：强引导 / 弱引导 / 自由探索
- 与主线的衔接意图
- 开场形式偏好：叙事式 / 大纲式 / 表单式等，只记录偏好

> 独立世界书通常不适用，跳过。

### 7. SFW / NSFW

- 成人程度 / 内容分级：SFW / 默认 SFW 可触发 NSFW / 主线 NSFW / 硬核 NSFW
- 性向与关系结构：性向倾向为异 / BL / GL / 双 / 灵活，关系结构为 1v1 / 后宫 / 多人 / 开放关系，是否允许 NTR
- NSFW 触发与节奏：是主线内容还是可选分支？触发方式为玩家主动 / 剧情驱动 / 角色主动
- 硬性边界 / 禁忌：绝对不希望出现的内容，先于喜好确认
- 性癖喜好：正向倾向列表，如温柔向 / 支配服从 / 束缚 / 角色扮演 / 言语刺激 / 身体描写侧重等，不替用户决定
- NSFW 笔触 / 文风：含蓄克制 / 露骨直白 / 感官情绪向 / 解剖式

> 允许任一子项回答「不涉及 / 暂不讨论」；未明确回答的不得推断默认值。

## 复杂剧情设计

当剧情存在多线、反转、阶段性揭示、玩家选择分支等复杂结构时，额外讨论并记录：

- **暴露时机**：哪些信息在什么阶段让玩家知道？
- **控制策略**：如何保证剧情推进不失控？（阶段边界、关键事件顺序、玩家自由度范围等）
- **未确定部分**：如果用户暂时没有想清楚，记录开放问题，留给后续创作规划或创作阶段继续确认

> 独立世界书无主线剧情时跳过本节。

## 从材料转化的衔接

当用户提供现成素材（轻小说、游戏脚本、小说等）时：

1. **先讨论**：围绕素材中没有覆盖或需要用户补充的主题、体验、剧情、风格，以及转化侧重（哪些内容优先提取、哪些可以弱化）进行讨论
2. **执行转化**：按 `references/conversion.md` 流程处理素材；叙事材料产出 `cards/{Project}/故事大纲.yaml`，结构化材料可直接使用原设定
3. **结合成果完成**：把转化成果中的世界观、角色、剧情、风格等信息提炼到大方向级别，写入 `design-spec.md`
4. **注意**：`design-spec.md` 仍是大方向描述

## 产出格式建议

Markdown，有段落约定，内部自然语言自由描述。参考结构：

```markdown
# Design Spec — [项目名]

## 项目定位
- 项目名称：...
- 形式：角色卡 / 独立世界书
- 主题：...
- 体验目标：...

## 世界观概念
...

## 角色方向
...

## SFW / NSFW
...

## 剧情设计
...

## 风格意向
...

## 开场构思
...
```

后续 tavern-ui 会在文件末尾追加 `## UI 设计` 段。
